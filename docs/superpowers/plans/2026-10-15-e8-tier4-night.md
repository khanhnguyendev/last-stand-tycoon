# E8 Tier 4 Night Side: Implementation Plan (phase 1 in detail)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phase 1 gives the four branches a real weakness off their lane, so that reading the lane markers pays in
tier 3. Phase 2 (planned at its start, D-314.16) adds tier 4.

**Architecture:**
- The weaknesses are numbers on existing systems: tower `kind_mults` and fence `damage_taken_mult_by_kind`.
- They are looked up through a kind class, so bosses share their kin's numbers.
- The lane-type bench's FLOOR rule is replaced by ON, OFF and NEUTRAL rules.
- The branch card gains a weakness row.
- The retune report gains the first-night band and measurement sets #5 and #6.

**Tech stack:** Godot 4.7.2, GDScript, GUT 9.7.1.

**Spec:** `docs/superpowers/specs/2026-10-15-e8-tier4-night-design.md` (read sections 3 and 5 before any task).
Decisions D-313 and D-314.

## Review Focus

1. **The Baron at tier 2:** the kind class gives the Baron the hare's multipliers. No Longbow exists before tier 3,
   so tier-2 play must not change. Task 1 checks `baseline_diff` and `baseline_rows` identical, and a unit test runs
   a Longbow against a Baron.
2. **A tie on the bench measure:** both runs lose 0 diner HP, or both fences never fall. ON and OFF must fail
   unless the tie-breakers separate the runs (spec 3.1). Task 2 tests 0 == 0 and INF == INF.
3. **The card on the smallest phone width:** the fourth line must not clip or overlap the joystick zone. Task 4
   extends the obstacle and clipping tests to the new height at 720x1280 and at the 40% shot size.
4. **A first night lost and retried:** FIRST_NIGHT_BAND counts it as 0, as FIRST_T3_NIGHT does. Task 5 has a unit
   test with one retried run.
5. **An old save with a branch built before E8:** it loads with the new values and nothing else changes. Task 3
   adds a load test from the committed v7 fixture `export/fixtures/tier3_cap_all_b.save.json`.

- [ ] **Step 2: Run** `./run_tests.sh unit`. Expected: FAIL (`kind_class` does not exist).
- [ ] **Step 3: Implement.**

```gdscript
# balance/monster_balance.gd
## E8 (D-314.10): the class a kind meets branch multipliers as. Bosses share their kin's numbers.
const KIND_CLASS := {&"baron": &"hare"}
static func kind_class(kind: StringName) -> StringName:
	return KIND_CLASS.get(kind, kind)
```

  Use the class everywhere a kind is looked up:
  - `attacker.gd`: `kind_mults.get(MonsterBalance.kind_class(target.get(&"kind")), 1.0)`.
  - `GameState.damage_fence`: `damage_taken_mult_by_kind.get(MonsterBalance.kind_class(attacker_kind), 1.0)`.
  - `GameState.fence_pass_damage`: check the class.
  - `BranchMath.fence_hold_seconds`: look up the class.
  - `BranchMath.pass_damage`: `kind_class(kind) in fence.pass_kinds`. Keep `pass_kinds = [&"hare", &"baron"]` as it
    is, so the result is the same.
  - `tier_bot.gd:127`: `kinds[i]` becomes `MonsterBalance.kind_class(kinds[i])`.
- [ ] **Step 4: Run** `./run_tests.sh unit`, `sim`, `sim-tiers-a`, `sim-tiers-b` and `bench`, then the three identity
  tools, alone. Expected: all green and all three identical, because no shipped multiplier names a hare or a Baron.
- [ ] **Step 5: Commit** `feat(e8): branch multipliers by kind class (the Baron is a hare)`.

### Task 2: The ON, OFF and NEUTRAL rules as pure functions

**Files:**
- Modify: `balance/branch_balance.gd` (add `@export var bench_m_on := 0.15`, `bench_m_off := 0.10`,
  `bench_m_neu := 0.15`, `bench_a_floor := 20.0`, each with a doc comment: fixed for E8, D-314.8)

**Interfaces:**
- Produces, as statics on `BranchBench`:
  - `on_rule(spec: Dictionary, refs: Array, order: Array) -> Dictionary`
  - `off_rule(spec: Dictionary, unbranched: Dictionary, measure: String, higher: bool) -> Dictionary`
  - `neutral_rule(spec: Dictionary, unbranched: Dictionary) -> Dictionary`
  - Each returns `{ok, measure, a, b, bound, why}`.
- Produces: `RULES`, a constant table of `[rule, branch, lane, measure, higher]`, one row per line of spec 3.1.
- Consumes: `beats_by_margin` (today's tie handling).

- [ ] **Step 1: Write failing unit tests** on synthetic result dictionaries:
  - **ON, Longbow siege:** lost 80 against unbranched 200 and Volley 150 passes (bound 0.85 × 150 = 127.5); lost 130
    fails. A 0 == 0 tie with no tie-breaker separating the runs fails.
  - **ON, Stone:** stands 70 against max(unbranched 30, Spike 40) passes (bound 1.15 × 40 = 46); INF against INF
    fails.
  - **OFF, Longbow hare:** lost 1200 against unbranched 1000 passes (bound 1.1 × 1000 + 20 = 1120); 1100 fails;
    0 against 0 fails.
  - **OFF, Spike siege (H):** stands 20 against unbranched 30 passes (bound 0.9 × 30 = 27); INF against INF fails.
  - **NEUTRAL:** lost 600 against unbranched 560 passes (bound 1.15 × 560 + 20 = 664); 700 fails; 0 against 0
    passes (it is one-sided).
  - **RULES:** the table has exactly the 11 rows of spec 3.1: 4 ON (one per branch), 3 OFF (no Stone wall),
    4 NEUTRAL.
- [ ] **Step 2: Run** `./run_tests.sh unit`. Expected: FAIL.
- [ ] **Step 3: Implement.** ON uses `beats_by_margin` against each reference, with the reference set to the better

  margins are read from `Balance.data.branches`. Remove `no_worse`, `FLOOR_ORDER` and `FLOOR_FAILS_WHEN` only in
  Task 3, where their callers change.
- [ ] **Step 4: Run** unit. Expected: PASS.
