# E5 slice 2: diner tier 3 — implementation plan

> **For agentic workers:** executed with superpowers:subagent-driven-development. One `implementer` per task, one
> `reviewer` pass per task, a whole-branch review at the end. The main session writes each task's brief from this
> plan and the spec at dispatch time.

**Goal:** tier 3 of the diner ladder (front lot, south-west lane, siege brute, level-3 branching, Baron von Hop), with
tier-2 growth readability first.

**Architecture:** tier-gated data (`TierBalance`, `MapLayout.*_for_tier`, `LanePlanner.lanes_for_tier`), a
`BranchBalance` resource read through one stats function per building, save schema 6. Nothing of tier 3 is reachable
until the tier-3 cost entry lands (the last task of phase 4), so phases merge one by one.

**Tech stack:** Godot 4.7.2, GDScript, GUT 9.7.1.

**Spec:** `docs/superpowers/specs/2026-10-07-e5-tier3-design.md` (binding; decisions D-261 to D-275).

## Global constraints

- Tier-1 identity: `tools/baseline_rows.sh 7` prints `rows 1-7 identical` after every task. `tools/baseline_diff.sh`
  prints `baseline identical` after every task except one that deliberately changes tier-2 balance (Task 4's cap
  decision), which re-records with an explained diff.
- Tiers 1 and 2 plans are byte-identical: `LanePlanner.LANES` and its draw order never change.
- Before the switch (Task 21) the top tier stays 2: no test may rely on tier 3 being reachable without adding the
  cost entry in its own setup (`Balance.data.tiers.tier_costs.append(1500)`, reset in `after_each`).
- Every number in `balance/`; every user string through `tr()`; randomness only through `Rng.stream`.
- Never drop, skip or weaken a test. A new sim needs a golden tick entry
  (`TICK_BUDGET_UPDATE=1 ./run_tests.sh sim-tiers`), committed with a reason.
- Hot files (`project.godot`, `CLAUDE.md`, `autoload/*`, `balance/*`, `world/main.gd`, `world/main.tscn`,
  `world/world.gd`, `run_tests.sh`, `tests/sim_ticks.golden.json`, `.github/workflows/*`) are edited only by the task
  that names them below, or by the main session from a wiring note.
- No perf run and no device check before Task 25 (D-260).
- Lessons from slice 1: a test must fail for a named wrong implementation (no self-comparison, no value the setup
  already had); state changes are placed at the right moment of the day/night cycle; a fix round never deletes a
  test; any mesh above ground level is checked through the game camera against zones, spots and pickups.

## Review focus

1. A tier-2 save loaded after the slice plays exactly as before (plan, layout, schema migration).
2. A hero crossing or resting near two branch pads never loses gold to the wrong pad.
3. A fence destroyed with a branch and partial payments on its pads: state after dawn and after a reload.
4. A tab closed at any point of the tier-3 dawn (reveal, layout switch, card pick).
5. Travelers alive at the moment of the layout switch (must be none; proven, not assumed).
